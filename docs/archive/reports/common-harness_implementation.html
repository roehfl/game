요약

D:/game 아래 게임들이 함께 쓰는 공통 하네스를 만들었다. hsl 하네스의 자기개선 루프(근거 수집 → Propose → Compose → 사용자 선택 → Reflect → 승인 뒤 반영)는 그대로 쓴다.

새로 더한 것은 편집마다 정하는 범위다. "다른 게임에서도 같은 결함이 같은 편집으로 막히는가"에 답해 이 게임 하네스만 바꾸거나 game 전체 공통 하네스를 바꾼다. 판단이 안 서면 게임 범위에 두고, 다른 게임에서 다시 관찰되면 공통으로 승격한다.

게임 세션은 상위 폴더의 .claude를 읽지 않는다(실측). 그래서 공통 스킬·서브에이전트는 정션으로 연결하고, 새 게임은 tools/new-game.sh로 만든다. 같은 날 S2가 끝난 hsl을 D:/game/hsl로 옮겨 첫 게임으로 연결했다.

범위 판정

판정 질문 다른 게임에서 같은 과제를 해도 같은 결함이 나고, 같은 편집으로 막히는가?

답범위결함이 있는 곳예
예공통에이전트 습관, 사용자와의 확인 방식, 도구·환경(Windows·Claude Code·git), 하네스 루프 자체hsl L-001 질문 완결, L-005 외부 전제 확인
아니오게임이 게임의 설계 결정, 장르 감각, 수치, 코드 구조, 문서 배치hsl L-009~L-011 전투 체감
판단이 안 섬게임—다른 게임에서 재관찰되면 승격

엔진·툴체인 지식은 그 엔진을 쓰는 게임이 하나면 게임 범위, 둘 이상이면 공통 스킬.

범위 × 종류 반영 위치

범위invariantdomain
게임<게임>/AGENTS.md, 게임 훅<게임>/.claude/skills·agents, <게임>/tools/
공통AGENTS.md, tools/harness-tool-log.sh, 틀의 훅.claude/skills·agents, tools/, templates/game/

교훈 ID는 공통 G-NNN, 게임마다 L-NNN. patch 경로는 patch/common/…(D:/game 기준), patch/game/…(게임 기준).

승격과 강등

게임 L-NNN→ (두 번째 게임 재관찰 · 게임 무관 근거)→ 공통 G-NNN
공통 G-NNN→ (어떤 게임에서 사용자 교정으로 안 맞음)→ 게임 L-NNN

승격은 "공통 추가 + 이 게임의 같은 문장 삭제"를 한 편집으로 낸다. 게임 LESSONS 행은 승격 → G-NNN으로 남는다. 다른 게임에 남은 중복은 그 게임의 다음 reflect에서 지운다.

결정 로그

#결정근거
1invariant/domain(종류)과 별도로 게임/공통(범위) 축을 더했다사용자 요구: 자기개선 방식은 유지하고 개선 방향에 따라 반영 위치를 나눔
2판단이 안 서면 게임 범위, 재관찰되면 승격한 게임의 취향이 모든 게임의 규칙이 되는 것을 막음(hsl 원칙 3의 확장)
3공통 스킬·서브에이전트를 디렉터리 정션으로 연결부모 .claude 미로드 실측. additionalDirectories는 신뢰하지 않은 폴더에서 무시되고 신뢰가 부모에서 이어지지 않음
4정션 제외는 게임 저장소의 .git/info/exclude에 적음공통 스킬이 늘거나 줄어도 게임 저장소에 커밋할 변경이 생기지 않음
5범위를 게임에서 공통으로 넓히는 확정은 사용자만 함공통 편집은 모든 게임에 미침
6한 세션은 다른 게임 폴더를 고치지 않음범위 이탈 방지. 중복은 그 게임의 다음 reflect가 정리
7도구 로그 실패 판정을 PostToolUseFailure 이벤트로 바꿈hsl 훅은 실패 0건 기록(S1 E12). 실패 때는 tool_response가 없고 Python 출력의 \r도 비교를 깸. 실제 세션으로 확인
8hsl L-001~L-008을 G-001~G-008로 옮기고 L-009~L-011은 남김판정 질문을 적용: 앞의 것은 게임과 무관, 뒤의 것은 hsl 전투 체감
9D:/game을 git 저장소로 만들고 허용 목록 방식 .gitignore로 게임 폴더를 뺌기본 하네스 = git HEAD 원칙. 새 게임 폴더가 자동으로 빠짐
10교훈 ID 접두를 G-/L-로 나눔AGENTS.md 주석만 보고도 어느 범위의 교훈인지 구분
11hsl은 S2가 main에 머지된 뒤, S2 돌아보기 전에 옮김진행 중이던 S2-3 계획(D:/hsl 경로 26곳)을 깨지 않고, S2 돌아보기를 두 범위 루프의 첫 실전으로 삼음(사용자 결정)
12hsl 자체 루프 파일은 지우고 공통 것을 정션으로 씀같은 이름 스킬은 연결이 건너뛰어지고, 같은 이름 서브에이전트가 두 벌 생김
