# /harness-reflect <과제 ID> [--probe]

Harness² 루프의 진입점. 루프와 범위 판정 기준은 공통 루트(`D:/game`, 게임 폴더의 상위)의 `harness/README.md`, 설계는 `docs/specs/2026-10-25-common-harness-design.md`.
과제 ID 형식은 `YYYY-MM-DD-<slug>`. `--probe`는 레벨 2에서 구현한다. 지금 주어지면 "미구현, probe-less로 진행"이라고 말하고 계속한다.

## 0. 과제 정의

- 위치를 정한다. 세션 폴더가 `D:/game/<게임>/`이면 게임 과제(위치 = 게임 이름), `D:/game`이면 공통 과제(위치 = `_root`, 게임 범위 편집 없음).
- `RUN = <세션 폴더>/harness/runs/<과제 ID>/`.
- `RUN/task.md`가 없으면 만든다. 내용: 과제 한 줄 설명, 완료 기준, 과제가 걸친 세션·커밋 범위, 위치.

## 1. 근거 수집 → `RUN/reference/evidence.md`

줄 번호가 근거 인용에 쓰이므로 항목마다 한 줄씩 쓴다.

1. **사용자가 바로잡은 지점** — 가장 먼저, 가장 강한 근거. 세션 안에서 사용자가 되돌리게 했거나 방향을 고친 발언을 하나씩 적는다. 이 세션에서 보이지 않으면 사용자에게 한 번 묻는다: "이 과제에서 제가 잘못 잡아 바로잡으신 지점이 있었나요?"
2. **결과** — 완료 기준 충족 여부. 코드 과제면 테스트·타입체크 출력 요약.
3. **변경** — `git diff --stat` 또는 만든 파일 목록. 범위 밖 파일(공통 하네스·다른 게임 포함)을 건드렸는지.
4. **과정** — `RUN/tool-log.jsonl`이 있으면 실패(`"error":"true"`)·재시도 횟수. 없으면 세션 기억으로 재시도·헤맨 지점.
5. **자기 보고** — 3줄 이내. 무엇을 모르고 헤맸나, 어떤 문서·도구가 없어서 추측했나.

## 2. Propose

`harness-proposer` 서브에이전트를 과제 ID·위치와 함께 호출한다. 결과: `RUN/candidates/invariant/`, `RUN/candidates/domain/`.

## 3. Compose

`harness-composer` 서브에이전트를 과제 ID·위치, 모드 `probe-less`로 호출한다. 결과: `RUN/DECISION.md`, `RUN/composed/`.

## 4. 사용자 선택

`DECISION.md`의 결정 표를 사용자에게 보이고 편집 번호별로 채택/보류/폐기와 범위(게임/공통)를 확정받는다. 표를 요약하지 말고 그대로 보인다. 공통 범위 편집이 있으면 "영향 범위" 절(닿는 게임 목록)도 같이 보인다. 사용자가 답하기 전에는 5·6으로 가지 않는다.

## 5. Reflect

`harness-reflector` 서브에이전트를 과제 ID·위치와 사용자 확정 결정(결정·범위)으로 호출한다. 결과: 게임 범위는 `<게임>/harness/library/<과제 ID>/`와 게임 `LESSONS.md`, 공통 범위는 `D:/game/harness/library/<위치>/<과제 ID>/`와 공통 `LESSONS.md`.

## 6. 기본 하네스 반영

채택된 편집만 라이브러리의 `patch/`에서 실제 경로로 복사한다.

- 게임 범위: `<게임>/harness/library/<과제 ID>/patch/` → 게임 폴더. `AGENTS.md` 편집에는 해당 `<!-- L-NNN -->` 주석을 단다.
- 공통 범위: `D:/game/harness/library/<위치>/<과제 ID>/patch/` → `D:/game`. `AGENTS.md` 편집에는 `<!-- G-NNN -->`. 공통 스킬을 추가·삭제했으면 `bash D:/game/tools/link-common.sh`로 모든 게임의 정션을 맞춘다. 공통 훅의 이벤트를 바꿨으면 각 게임 `.claude/settings.json`도 반영 목록에 넣는다.

복사 전에 반영할 파일 목록을 저장소별(게임 저장소 / 공통 저장소 `D:/game`)로 나눠 보이고 승인을 받는다. 커밋은 하지 않는다.

## 하지 않는 것

- 요청 없이 시작하기. 요청을 받은 뒤 사용자에게 명령을 직접 입력하게 하거나 단계마다 진행을 묻지 않는다(묻는 곳은 1단계에서 교정 지점이 안 보일 때, 4단계 선택, 6단계 반영 승인뿐). <!-- G-008 -->
- 근거 없는 편집의 채택. Composer가 "보류"로 둔 것을 스킬이 올리지 않는다. Composer가 정한 범위를 스킬이 넓히지 않는다 — 게임에서 공통으로 바꾸는 것은 사용자가 4단계에서만 한다.
- 다른 게임 폴더의 파일 고치기. 승격으로 생긴 다른 게임의 중복 문장은 그 게임의 다음 reflect에서 지운다.
- `harness/runs/`의 내용을 라이브러리로 통째로 옮기기. 승격되는 것은 EXPERIENCE.md·patch·LESSONS 한 줄이다.
